## 1. Summary

Folio is a desktop app that works like VS Code with Claude Code built in, but for people who do not code.

You open a folder. On the left you see your files with plain names and friendly icons. In the middle you open things in tabs: a PDF, a Word-style document, a note, a drawing, or an interactive page. On the right is **Funza**, the assistant. Funza can read what you have open, explain the part you selected, and, with one button, make flashcards, a quiz, a summary or a document for you. It can tidy your files or build a small interactive page. Before it changes anything in your folder it asks you in plain language, and everything it does can be undone.

Funza adapts to who you are. In **Student** mode its buttons are Explain, Summarise, Flashcards, Quiz and Study plan. In **Everyday** mode they are Explain, Summarise, Write a document, Draft a reply and Organise files. You pick a mode the first time you start Folio and can change it any time in Settings.

Folio is not a code editor. There is no terminal, no file extensions in your face, and no settings you need to understand before you start. It has a light mode and a dark mode, and it looks like the Funza prototype: cream, coral, rounded, friendly, with the brain mascot.

Under the hood, Funza uses AI engines from Anthropic (Claude), Google (Gemini) and others. The person never sees those names in the main interface; they see Funza, and a choice of Fast, Standard or Deep. The engines are listed only in Settings, where the privacy notice and the plan live. Paying for the Pro plan happens on the Folio website in the browser, never inside the app.

The first release (1 December 2026) covers Windows laptops. Mac follows in winter. Voice conversation with Funza and an interactive Tutor tab (Funza watches your whiteboard and talks you through a problem) are planned for winter 2027.

### What this product is in one sentence

> A folder on your computer, plus Funza, a helper that can read it, explain it, and make things in it, with your permission.

## 2. Why we are pivoting

The original product (`docs/04-workshop-3`) was a study tool for undergraduates: open a course PDF, select a passage, get an explanation with a page reference, then make flashcards and quizzes. Four things pushed us wider:

1. **The core value is not student-specific.** "Explain the thing in front of me and cite where it came from" is what office workers, parents doing taxes, and seniors reading medical letters need too.
2. **Reading is only half the job.** Every person we have talked to reads a PDF and then has to *produce* something: a summary document, notes, a filled-in form, a diagram. The old scope stopped at reading.
3. **Agents arrived.** Tools like Claude Code can now look at a folder, create files and run small tasks. That power exists only for developers. Non-technical people have no safe way to use it.
4. **Our prototype already drifted.** Chop's October prototype is an adaptive tutor with a talking mascot, not the planned reader. That tells us the team's interest is in an assistant that *does things with you*, not a PDF reader with a chat box. The prototype's name, look and mascot become Funza, the assistant.

What stays from the original: local-first (your files never leave your computer unless you ask), explanations that cite the page, flashcards and quizzes, a picker with free engines, and the Electron + React desktop decision.

What changes: the home object is a *folder*, not a *course*; the app creates and edits documents, notes, drawings and pages, not only reads PDFs; Funza is an assistant with tools, buttons and permissions, not a question box; and the primary user is any non-technical person, with students as the pilot testers and Student mode as a first-class way to use it.

### 3.3 Jobs to be done

1. Open my stuff without fuss.
2. Understand what I am looking at.
3. Make something from it (a document, notes, flashcards, a diagram, a page) with one button.
4. Keep it organised without learning a file system.
5. Get help from Funza without worrying it will break or lose my files.

## 4. Design principles

1. **Plain words everywhere.** "Your folder", not "workspace". "Document", "Note", "Drawing", "Page", not ".docx", ".md", ".excalidraw", ".html". Extensions are hidden by default and shown on hover or in Settings.
2. **Buttons before prompts.** The common jobs (explain, summarise, flashcards, quiz, write a document, organise) are buttons with a small options sheet. Typing to Funza is always possible, never required.
3. **Nothing happens to your files without a card.** Every create, edit, delete or run is a permission card the person can read in five seconds. Deletes go to the Recycle Bin. The last change can always be undone.
4. **One editor to learn.** Documents and notes use the same toolbar. The PDF viewer and the whiteboard keep their own tools small.
5. **Funza shows its work.** Every explanation says which file and page it came from, and an activity log lists what Funza did.
6. **Funza is one character, whatever engine runs it.** The person talks to Funza. Engine names appear only in Settings.
7. **Works offline for viewing and editing.** Only Funza needs the internet.
8. **No setup.** No account and no API key are needed to start. Install, pick a mode, open a folder, go.
9. **Looks like Funza.** Cream background, coral accent, rounded corners, soft shadows, the Nunito font and the brain mascot, in light and dark.

### 6.5 Files panel

The folder is shown exactly as it is on disk, with these presentation rules:

- Plain names, no extensions. A small pastel type tag (PDF, Doc, Note, Draw, Page, Image, Folder) sits at the right of each row, and the icon matches the type.
- Hidden: files and folders starting with a dot, `node_modules`, `.folio` (the app's own data), desktop.ini and Thumbs.db.
- Sorting: folders first, then by name. "Sort by recent" is a toggle.
- **[+] New** offers: Document, Note, Drawing, Page, Folder. In Student mode it also offers Flashcards and Quiz, which open the matching Funza sheet (6.12).
- Right-click: Open, Open with (the built-in viewer or the computer's default app), Rename, Move to folder, Duplicate, Delete (moves to Recycle Bin), Show in File Explorer / Finder, Ask Funza about this.
- Drag to move. Drag from the panel into the chat to attach a file to a question.
- Changes made outside the app (another program saves a file) show up within two seconds.
- Files Funza creates are normal files in the folder, named plainly ("Osmosis flashcards", "Summary of Chapter 3"). Folio never hides Funza's output from the person.

**What the app stores, and where.** Folio keeps its own data in a hidden `.folio` folder inside the opened folder: chat history, the activity log, undo snapshots, highlights and the saved tab layout. It is hidden in the Files panel, it is safe to delete, and deleting it never touches the person's own files. App-wide settings (mode, theme, recent folders, the Funza token, the plan) live in the per-user application-data folder provided by the operating system.

### 6.6 PDF tab

- Continuous scrolling, zoom, fit width, page thumbnails, find in text, page number box.
- Select text (or drag a box on a scanned page) and a small toolbar appears with the mode's quick actions: Student: **Explain**, **Summarise**, **Flashcards**, **Quiz**, **Add to notes**, **Ask...**; Everyday: **Explain**, **Summarise**, **Write a document**, **Add to notes**, **Ask...**
- Explain streams into the Funza panel and ends with the file name and page: "(Chapter 3, page 12) [Go to page]".
- Highlights and sticky notes are saved and reappear next time (Phase 2).
- A scanned page shows "This page is a picture, so text cannot be selected. Draw a box around the part you want explained instead." (Text recognition for scanned pages comes in Phase 2.)
- Only the selected text and the text of that page are sent to the engine. "Ask about the whole document" is a separate, explicit action that explains what will be uploaded before it does it (section 9.5).

### 6.7 Document tab (Word-style, saves .docx)

- Opens existing `.docx` files and creates new ones.
- Toolbar: Heading 1 to 3, Bold, Italic, Underline, Highlight, Bulleted and numbered lists, Table, Image, Align, Undo, Redo. Nothing else in Release 1.
- Autosave every few seconds with a "Saved" indicator. Save as. Export as PDF.
- Opening a document with features the editor cannot show (headers and footers, comments, tracked changes, text boxes) shows a one-line notice: "Some formatting from Word is not shown here and may be lost if you save. A copy of the original is kept." The copy goes to `.folio/originals` the first time such a file is saved.
- "Ask Funza about this document" and "Improve the selected text" send only the selection (Release 1) and apply suggestions as accept-or-reject edits (Phase 2).

### 6.8 Notes tab (Markdown)

- Notes use the same toolbar as documents and are saved as `.md` files, so they also open in any other notes app.
- Quick note: Ctrl+N creates "Note - 20 Oct 2026" in the folder.
- "Add to notes" from a PDF selection appends the quote with the file name and page.
- The Notes panel in the activity bar lists only notes, newest first.

### 6.9 Whiteboard tab (Drawing)

- Freehand pen (with pressure on pen devices), shapes, arrows, text, select, erase. Touch and stylus work.
- Saved as a drawing file and a PNG preview side by side, so the drawing opens in the app and the picture opens anywhere.
- **Ask Funza about this drawing** sends a PNG of the canvas with the question ("Is my force diagram right?").
- Funza can draw on the canvas (add labelled shapes) when the person asks, through the same permission card as any other change.

### 6.10 Page tab (interactive pages Funza makes)

When the person asks for something interactive ("make me a quiz page for this chapter", "build a timeline of these events", "make a unit converter"), Funza writes an HTML page into the folder. It is a real file, named plainly, and opens in a **Page** tab inside the app.

- The page runs in a sandbox: no internet access, no access to other files, no pop-ups. Everything it needs is inside the one file.
- **Open in browser** and **Edit with Funza** buttons sit above the page.
- The person can delete it like any other file.

### 6.11 Funza panel

- Header: mascot, the name Funza, and the level picker (**Fast**, **Standard**, **Deep**). The picker never shows engine or company names; the tooltip says "Deep is slower, better at hard questions, and uses more of your daily allowance."
- **Quick actions** row: the mode's buttons (6.12). Each opens a small sheet, not a prompt.
- **Suggestions**: up to three context chips Funza offers without being asked ("You opened Chapter 3. Want flashcards from it?" [Yes] [Later]). Dismissed suggestions do not come back for that file. Suggestions can be turned off in Settings.
- Chat with streaming replies. A context strip above the input shows what Funza can see right now: the open file, the current selection, and attached files. Each chip can be removed.
- Steps appear as Funza works: "Reading Chapter 3 (pages 10 to 14)", "Creating Osmosis flashcards", with permission cards when needed.
- **Stop** button during a reply. **New chat**. History per folder, searchable.
- **Usage** in the status bar: "3 of 60 requests today". At the limit, Folio switches to Fast and says so; Pro raises the limit (6.15).

### 6.12 Quick actions and their sheets

Each quick action is a button that opens a small sheet with two or three choices, then runs. Funza builds the result *and the screen for it*: a flashcard deck opens in a deck viewer, a quiz opens in a quiz viewer with marking, a summary opens where the person chose. Nobody has to type "make me 10 flashcards from pages 3 to 5 as a markdown file".

**Student mode**

| Button | Sheet | Result |
|---|---|---|
| Explain | none; uses the selection, or asks "Select a part first" | reply in the panel with file and page |
| Summarise | Length: Short / One page. Put it: In the chat / In a new note / In a new document | reply, note or document |
| Flashcards | From: Selection / Pages [3] to [5] / Whole file. How many: 5 / 10 / 20 | permission card, then "Chapter 3 flashcards" opens in the deck viewer (flip, know it / don't know it, shuffle) |
| Quiz | From: same choices. Questions: 5 / 10. Type: Multiple choice / Short answer | permission card, then "Chapter 3 quiz" opens in the quiz viewer (answer, instant marking, page reference for each wrong answer) |
| Study plan | Exam date, days per week | permission card, then "Study plan" note with a day-by-day list linking to files and pages |
| Add to notes | pick a note or "New note" | quote appended with file and page |

**Everyday mode**

| Button | Sheet | Result |
|---|---|---|
| Explain | none | reply in the panel with file and page |
| Summarise | same as Student | reply, note or document |
| Write a document | Type: Summary / Letter / Report / Fill in the blanks of this form. Based on: Selection / This file / My notes. Tone: Plain / Formal | permission card, then the document opens in the Document tab |
| Draft a reply | Paste the message or pick a file. Tone: Friendly / Formal. Length: Short / Full | draft opens as a note, with Copy |
| Organise files | Funza proposes a folder structure (preview tree with every move listed) | one permission card listing all moves; Undo reverts all of them |
| Add to notes | same as Student | quote appended |

Both modes share the chat for anything the buttons do not cover. Buttons are plugins (section 10), so adding a mode or a button does not touch the shell.

### 6.13 Permission cards and the activity log

Every change to the folder is a card built from three pieces: what Funza wants to do, which file, and Funza's own reason in one sentence.

```
+------------------------------------------------------------+
|  [mascot]  Funza wants to delete "Notes (1)" (Note, 12 KB)  |
|  Why: it is an empty copy of "Notes".                       |
|  It will go to the Recycle Bin, so you can get it back.     |
|                                                             |
|  [ Allow once ]   [ Don't allow ]                           |
+------------------------------------------------------------+

+------------------------------------------------------------+
|  [mascot]  Funza wants to create "Osmosis flashcards"       |
|  Why: you pressed Flashcards for Chapter 3, page 12.        |
|                                                             |
|  [ Allow once ]  [ Allow in this folder ]  [ Don't allow ]  |
+------------------------------------------------------------+

+------------------------------------------------------------+
|  [mascot]  Funza wants to edit "Lab report" (Doc)           |
|  Why: fix the units in the results table.                   |
|     Before: "12 ml of water"     After: "12 mL of water"    |
|     (3 more changes)                          [ Show all ]  |
|  [ Allow once ]  [ Allow in this folder ]  [ Don't allow ]  |
+------------------------------------------------------------+
```

Rules:

| Action | Card? | "Allow in this folder" offered? | Safety net |
|---|---|---|---|
| Read a file, list the folder | No, shown as a step line | n/a | Only inside the opened folder |
| Create a new file | Yes, first time per folder | Yes | n/a |
| Edit an existing file | Yes, with before/after | Yes | Snapshot taken first; Undo available |
| Overwrite, delete, rename over an existing file, move many files | Always | No | Snapshot; deletes go to the Recycle Bin |
| Run a script | Always, only if enabled in 6.3 | No | Runs in a sandbox with no network; output shown in chat |
| Anything outside the folder, any network access | Never allowed | n/a | Blocked in the app, not just in the prompt |

The **activity log** ("What Funza did") lists every change with a time stamp and an **Undo** button for the most recent ones. It is reachable from the Funza panel header and from Search actions.

### 6.14 Search actions (Ctrl+K)

A single box that finds commands and files by plain words. "dark" finds "Switch to dark mode"; "flash" finds "Flashcards from selection"; "lab" finds "Lab report". Recently used commands appear first. Every command in the app is registered here, which is also how plugins expose their features (section 10).

## 9. AI architecture

### 9.1 Which engines, and how Folio talks about them

Funza is the only name the person sees. Behind it, Claude (Anthropic) is the first-class engine; free engines stay available for cheap jobs and as a safety net for the budget. The three levels map to engines like this:

| Level in the UI | Engine behind it | Settings |
|---|---|---|
| Fast | Gemini 2.5 Flash free tier, Groq Llama 3.3 70B, OpenRouter free models; chat and quick actions only, no file tools | via the provider layer |
| Standard (default) | Claude Sonnet 5.5, `claude-sonnet-5-5`; quick actions on Claude Haiku 5.5, `claude-haiku-5-5` | effort medium for the agent, low for quick actions |
| Deep | Claude Opus 5.5, `claude-opus-5-5` | effort medium; Pro only in R2 |

Jobs behind the scenes:

| Job | Engine | Settings | Why |
|---|---|---|---|
| Funza chat with tools (the agent) | Claude Sonnet 5.5 (fallback Haiku 5.5) | streaming, tool runner, up to 12 tool steps, server-side fallback on refusals | Reliable tool use at half the price of Opus |
| Explain, Summarise, Flashcards, Quiz, Study plan, Write a document | Claude Haiku 5.5 | effort low, structured output for cards, quizzes and plans; input = selection + page text | Very cheap and fast; the sheet gives the engine exact parameters, so results are consistent |
| Organise files, Draft a reply (R2) | Claude Sonnet 5.5 | structured output: a move plan the card can list | Needs judgement |
| Whole-document Q&A (R2) | Claude Sonnet 5.5 | Files API upload, prompt caching with a 1-hour lifetime, citations on | About $0.50 per session instead of $4 without caching |
| Whiteboard and Tutor images (R2) | Claude Sonnet 5.5 | PNG scaled to about 1280 px (about 1,200 tokens, under a cent per image) | Geometry and diagrams |
| Bulk work no one is waiting for (R2) | Batch API on Haiku or Sonnet | 50% off | Pre-making decks overnight |

Prices (per million tokens, Anthropic list prices on 19 October 2026): Opus 5.5 $4 in / $20 out; Sonnet 5.5 $2 / $10; Haiku 5.5 $0.10 / $0.50 for prompts up to 100K tokens. Cache reads cost 5 to 10% of the input price.

Why not the Claude Agent SDK (Claude Code as a library)? It needs a native command-line binary bundled per operating system, it only works with Claude (so the Fast level would break), and it is built around a terminal. We need our own tools (documents, PDFs, pages), our own quick actions and our own permission cards anyway, so we build a small agent loop with the official Anthropic SDK's tool runner. The Agent SDK remains an option for a later "power mode".

### 9.2 The proxy

A small serverless service the team runs (free tier). It holds the Anthropic key and the free-provider keys. The app sends a per-install token (or an account token for Pro). The proxy:

- allows only the engines in the table above and caps `max_tokens` per job (4,096 for quick actions, 16,000 for the agent);
- enforces a daily request cap per install (60 in the pilot), per plan once accounts exist, and a monthly spend cap;
- records usage from each response so the app can show the meter;
- forwards streaming responses unchanged.

An account-level spend limit is also set in the Anthropic Console as a hard stop. "Use my own API key" (Settings, advanced) bypasses the proxy for people who want it.

### 9.3 The agent and its tools

The Funza panel runs an agent loop: the engine receives the chat, the context strip and the tool list; it may call tools; each tool call goes to the app's main process, which decides (automatic for reads, a card for changes), performs the action inside the folder, and returns the result; the loop continues until the engine finishes or 12 steps have passed.

Quick actions use the same tools but skip the free-form step: the sheet fills in the parameters, the job runs on the cheap engine with a structured output, and the result goes through the same permission card and the same viewers.

Every tool takes a `reason` field the engine must fill in with one plain sentence. That sentence is printed on the card, after "Funza wants to...".

| Tool | What it does | Permission tier |
|---|---|---|
| `list_files` | List a folder inside the open folder | automatic |
| `read_file` | Read a note, document (as text), page or text file | automatic |
| `read_pdf_pages` | Text of a page range with page markers | automatic |
| `get_selection` | The current selection, with file and page | automatic |
| `write_file` | Create a note or page; overwrite needs a card every time | create / overwrite |
| `create_document` | Create a .docx from headings, paragraphs and lists | create |
| `delete_file` | Move a file to the Recycle Bin | always ask |
| `edit_file` (R2) | Replace text in a file, with before/after preview | edit |
| `move_files` (R2) | Apply a list of moves and new folders (Organise files) | always ask, one card for the whole plan |
| `run_script` (R2) | Run a short script in a sandbox, no network | always ask |
| `get_whiteboard_image` (R2) | PNG of the current canvas | automatic |
| `add_to_whiteboard` (R2) | Add shapes to the canvas | edit |

The agent process has no direct file access of its own. It can only ask the main process, which checks that every path is inside the open folder before doing anything.

### 9.4 Permission tiers

See 6.13. The tiers are implemented in the main process, remembered per folder, and shown in Settings so the person can reset them.

### 9.5 PDF understanding: selection first, whole document on request

Release 1 sends only the selected text and the text of its page, which satisfies the original privacy requirement (TR-6) and keeps the cheap-engine prompts tiny. Page references come from the viewer, so citations are exact.

Release 2 adds "Ask about the whole document": the PDF is uploaded once through the Files API, cached for an hour, and questions get page-level citations from the engine. The dialog that enables it says what will be uploaded and that the file is deleted from the provider when the session ends. Fast is never used for this.

### 9.6 Cost model and guardrails

For one person in one session (a 100K-token PDF cached once, 20 questions):

| Routing | Cost per session | 20 people x 10 sessions |
|---|---|---|
| Opus 5.5 everywhere | about $1.00 | about $200 |
| Sonnet 5.5 everywhere | about $0.50 | about $100 |
| Haiku for quick actions, Sonnet for the agent (the plan) | about $0.20 to $0.35 | about $40 to $70 |

The project budget is US$150 in total, so the default routing is Haiku first, Sonnet for the agent, Opus only when the person picks Deep. Guardrails: prompt caching everywhere; per-install daily caps; monthly spend limit; engine locked per conversation; Fast as the fallback when limits are hit. Quick actions help here: a sheet-driven job is a short, fixed prompt on the cheapest engine.

### 9.7 Voice and the Tutor tab (winter)

Anthropic does not offer speech-to-text or text-to-speech. Electron's built-in browser speech recognition does not work (it needs a Google key Electron does not ship). The pipeline is: microphone capture in the app, streaming speech-to-text from a paid service (Deepgram Nova-3 at under a cent per minute, or OpenAI's realtime transcription), the engine streaming the reply, and text-to-speech spoken sentence by sentence while the mascot talks (the operating system's voices for free in the pilot; a natural-sounding service later at roughly 3 to 5 cents per minute). The Tutor tab adds a canvas image to each turn.

### 9.8 Privacy

- Anthropic's API does not use customer data for training and deletes inputs and outputs within 30 days; Files API uploads stay until the app deletes them.
- Gemini's free tier may use data to improve Google's products. The privacy notice says so, and Fast is never used for whole-document uploads.
- Nothing is sent anywhere without an action the person took (a question, a button).
- If any pilot participant is under 18, Anthropic's requirements for products serving minors apply and must be checked before the pilot.

## 10. Plugin architecture

The app is a small shell plus plugins. A plugin is a module in the repo that registers what it contributes; there is no marketplace and no third-party loading in this product.

```ts
interface Plugin {
  id: string;                 // "pdf", "docs", "notes", "whiteboard", "pages", "funza", "tutor", "mode-student", "mode-everyday"
  activate(ctx: PluginContext): void;
}

interface PluginContext {
  registerEditor({ id, match: string[], label, icon, component, priority });   // which files it opens
  registerView({ id, location: "activityBar" | "funzaPanel" | "statusBar", label, icon, component });
  registerCommand({ id, title, keywords, shortcut, run });                     // appears in Search actions
  registerQuickAction({ id, modes: ("student" | "everyday")[], label, icon, sheet, run });  // the buttons in 6.12
  registerSuggestion({ id, modes, when: (context) => boolean, text, run });    // the chips in 6.11
  registerAiTool({ name, description, schema, tier, handler });               // appears in the agent's tool list
  registerNewFileType({ label, extension, template, modes? });                 // appears under [+] New
  registerSetting({ id, label, type, default });
}
```

Built-in plugins in R1: Files, PDF, Documents, Notes, Funza panel, Student mode (its quick actions, suggestions and viewers), Everyday mode (Explain, Summarise, Write a document). Stretch or R2: Whiteboard, Pages, the rest of Everyday, Tutor. The Tutor plugin's activity-bar slot is reserved in R1 so the shell does not change later.

Adding a new tab type, quick action or mode means adding one folder under `plugins/` and calling `activate`; the shell, Search actions, the New menu, the Funza panel and the agent's tool list pick it up.
