## 2. Target architecture

### 2.1 Process model

```
+---------------------------------------------------------------+
|  Electron main process (Node)                                  |
|   window, menus, theme, recent folders, mode, updates          |
|   fs service  <-- every path checked: inside the open folder?  |
|   permission policy + per-folder memory                        |
|   snapshots (undo) and Recycle Bin                             |
|   agent host: starts the Funza process, relays tool requests   |
+------------------+----------------------------+----------------+
                   |  IPC (typed bridge)        |  messages
+------------------v-----------+   +------------v---------------+
|  Renderer (React, sandboxed) |   |  Funza utility process     |
|   shell: Home, Workspace,    |   |   Anthropic SDK tool runner|
|   tabs, Search actions,      |   |   quick-action jobs        |
|   status bar, theme          |   |   tools -> ask the host    |
|   plugins: files, pdf, docs, |   |   no file access of its own|
|   notes, whiteboard, pages,  |   |   streams tokens to host   |
|   funza, mode-student,       |   +------------+---------------+
|   mode-everyday, tutor       |                | HTTPS
+------------------------------+   +------------v---------------+
                                   |  Proxy (serverless, ours)  |
                                   |   holds keys, engine list, |
                                   |   caps, usage log, plans   |
                                   +------------+---------------+
                                                |
                                     Anthropic API / Gemini / Groq / OpenRouter
```

Key rules: the renderer never touches the file system directly; the Funza process never touches it either. Only the main process does, and only inside the open folder.

### 2.5 Funza messages

```ts
type ToolRequest = {
  runId: string; callId: string; tool: string; input: Record<string, unknown>;
  tier: "auto" | "ask" | "confirm";           // confirm = no "allow in this folder"
  preview?: { before?: string; after?: string; moves?: { from: string; to: string }[] };
  plain: string;                               // the sentence shown on the card, after "Funza wants to"
};
type PermissionResult = { runId: string; callId: string; decision: "allow" | "allow-folder" | "deny" };
type FunzaEvent =
  | { type: "delta"; runId: string; text: string }
  | { type: "tool_request"; req: ToolRequest }
  | { type: "tool_done"; callId: string; ok: boolean; summary: string }
  | { type: "usage"; input: number; output: number; cacheRead: number }
  | { type: "mood"; mood: "happy" | "thinking" | "celebrating" | "sad" }
  | { type: "done"; stopReason: string }
  | { type: "error"; code: string; message: string };
type QuickActionJob =
  | { kind: "flashcards"; source: Source; count: 5 | 10 | 20 }
  | { kind: "quiz"; source: Source; count: 5 | 10; type: "mcq" | "short" }
  | { kind: "summary"; source: Source; length: "short" | "page"; target: "chat" | "note" | "document" }
  | { kind: "study-plan"; examDate: string; daysPerWeek: number }
  | { kind: "document"; source: Source; docType: "summary" | "letter" | "report" | "form"; tone: "plain" | "formal" };
type Source = { type: "selection" } | { type: "pages"; file: string; from: number; to: number } | { type: "file"; file: string };
```

Flow for chat: the Funza panel calls `funza.run`; the main process forwards it to the Funza process; the process runs the Anthropic tool runner (`claude-sonnet-5-5`, streaming, effort medium, `max_tokens` 16,000, at most 12 tool steps, server-side fallback enabled); each tool's `run()` posts a `ToolRequest` to the host and waits; the host decides by policy or shows a card; approved actions run through the same fs service as the bridge, after a snapshot; text deltas and mood changes stream to the panel. Conversation history is append-only (editing an earlier message starts a new run), which keeps prompt caching effective and avoids the API's history-editing check.

Flow for a quick action: the sheet produces a `QuickActionJob`; `jobs.ts` builds a fixed prompt from it, runs it on `claude-haiku-5-5` (or the Fast engine) with a structured output, and then calls the same `write_file` or `create_document` tool, so the same card and the same viewers apply.

### 5.3 Bazaar demo script (24 November, 3 minutes)

1. Launch Folio. Pick Student. Open the sample folder from Home. Point out plain names and pastel tags.
2. Open the PDF, select a paragraph, press Explain. Funza's mascot tilts into "thinking", the answer streams with "(Chapter 3, page 12)". Click Go to page.
3. Press **Flashcards**, choose pages 3 to 5 and 10 cards, press Create. A card appears: "Funza wants to create 'Chapter 3 flashcards'". Allow. The file appears in the Files panel and the deck viewer opens; flip a card. The mascot celebrates.
4. Type "delete the empty note". The card says it will go to the Recycle Bin. Allow. Open the activity log and press Undo. The note is back.
5. Switch to Everyday in Settings: the buttons change to Explain, Summarise, Write a document. Toggle dark mode.

## 10. Repository and ways of working

- **Branches:** `main` is always releasable; feature branches per issue; the other person reviews every pull request (as in `09. Project Roles and Responsibilities`).
- **Issues:** close or re-label issues #1 to #18 against the new plan; create one issue per row of the week-by-week table with the milestone "ENSE 400 - Fall 2026" or "ENSE 477 - Winter 2027".

- **`vlog1.mp4`:** untrack it (`git rm --cached`), add `*.mp4` to a root `.gitignore`, host the video on YouTube and link it from the README. Do not rewrite history. Never commit Vlog 2 or 3.
- **Documents:** course deliverables stay PDFs in `docs/`; product documents (this folder) are Markdown so they can be diffed in pull requests.
- **Secrets:** no `.env` files committed; proxy and website secrets in Cloudflare and Stripe; `.env.example` lists names only.
- **Names in code:** the app is `folio`, the assistant is `funza`; engine names live only in `proxy/` and `src/agent/`.

## Appendix A. Change request summary for Dr. Maciag

**Project:** AI Learning Environment (prototype name Funza), ENSE 400/477, Aubin Chriss Izere and Chop Kur.
**Date:** 20 October 2026.
**Requested change:** widen the product from a student PDF study tool to **Folio**, a general-purpose desktop workspace for non-technical people, with **Funza** as the assistant inside it, keeping every Fall requirement and the Fall schedule.

**What stays the same**
- Electron + React desktop app, Windows first, macOS in winter (TR-1).
- Local-first: files stay on the device; only the selection and its page are sent by default (TR-6).
- No API keys in the app; a hosted proxy (TR-5).
- Fall deliverables: folders, PDF reader, selection, page-anchored explanations, a picker, flashcards, quizzes, history, privacy notice, fallback on errors, scanned-page notice (FR-1 to FR-12).
- Winter deliverables: accounts, Pro, usage limits, spaced review, voice, OCR (FR-13 to FR-18).
- Dates, milestones, team roles, pull-request review, Kanban board.
- The Funza name, look and mascot from the October prototype.

**What changes**
1. **Target user:** any non-technical person, chosen through a Student or Everyday mode at first launch. Students remain the pilot testers and Student mode keeps every Fall feature. Personas in PRD section 3.
2. **Scope additions** (previously listed as exclusions in `06. Project Scope Statement`): Word-style documents saved as .docx; notes; a whiteboard with annotation; interactive pages Funza makes.
3. **Funza becomes an assistant with buttons and tools** that can create, edit and delete files in the opened folder, with a permission card before every change, undo and Recycle Bin. Flashcards and quizzes become one-button actions that create files and open in viewers.
4. **Claude as the first-class engine** (Sonnet 5.5 standard, Haiku 5.5 for quick actions, Opus 5.5 on request) with the free engines kept as the Fast level; engine names shown only in Settings. Budget reallocated: up to US$100 for API use, the Apple fee only if the iPad or Mac build goes ahead.
5. **Pro plan is bought on the Folio website in the browser**, not inside the app (winter).
6. **TR-3 (SQLite)** deferred to winter; Release 1 stores history as files inside a hidden app folder.
7. **TR-6 amended:** the default stays selection-only; "Ask about the whole document" becomes an explicit opt-in in winter.
8. **FR-19 (iPad)** becomes a February go/no-go because Electron does not run on iPad.

**Why**

- The team's October prototype already moved toward an assistant that acts, not a reader with a chat box.

**Effect on grading documents:** the requirement IDs in `05. Project Requirements` all map to the new requirement set (PRD Appendix A). We propose to submit the PRD and this plan as an addendum rather than rewriting the Workshop 3 PDFs, unless you prefer updated PDFs.

const Deck = z.object({
  title: z.string(),
  cards: z.array(z.object({ front: z.string(), back: z.string(), page: z.number() })).min(5),
});
export async function flashcardsJob(job: Extract<QuickActionJob, { kind: "flashcards" }>, text: string) {
  const reply = await client.messages.parse({
    model: "claude-haiku-5-5",
    max_tokens: 4000,
    output_config: { effort: "low", format: zodOutputFormat(Deck) },
    messages: [{ role: "user", content: `Make exactly ${job.count} flashcards from this text. Keep each page number.\n\n${text}` }],
  });
  return reply.parsed_output;   // then: write_file("<title>.flashcards.md") through the normal card, open DeckViewer
}

Path guard (main process):

```ts
export function insideFolder(root: string, candidate: string): string {
  const resolved = fs.realpathSync(path.resolve(root, candidate));
  const rel = path.relative(fs.realpathSync(root), resolved);
  if (rel.startsWith("..") || path.isAbsolute(rel)) throw new Error("outside-folder");
  return resolved;
}
```
